# BCC Shield 360

**Активная экосистема кибербезопасности для мобильного банкинга Банка ЦентрКредит.**
ITU Hackathon 2026 · BCC Bank.

Демо-приложение на Next.js 14 (App Router) + React 18 + TypeScript + Tailwind CSS.
Один экран содержит мобильный интерфейс банка (395 × 852) и «Пульт симуляции атак»
для жюри, который в реальном времени меняет риск-профиль клиента.

---

## Что внутри

| Модуль | Назначение |
| --- | --- |
| **Unified Risk Engine** | Складывает независимые факторы риска в единый балл 0–100 и выбирает решение: `ALLOW` → `COOL_DOWN` → `GUARDIAN_APPROVAL` → `BLOCK`. |
| **Transfer + SafeCall** | Переводы с защитой от телефонного мошенничества: баннеры активного вызова, вставка из буфера, кулдаун 10 секунд и три контрольных вопроса. |
| **TrustLens** | Анти-спуфинг радар для звонков, кодовое слово `АЛТЫН-739`, криптографическая квитанция и проверка подписи. |
| **GuardPay** | Семейный мульти-подпись: замороженный платёж на 380 000 ₸, одобрение или блокировка, счётчик спасённых средств. |
| **AI Scam-Scanner** | Разбор реальных казахстанских скриптов мошенников, подсветка триггеров, API `/api/scam-analyze` и активация повышенной защиты. |

### Формула риска

```
неизвестный звонок        +35
вставка из буфера         +20
сумма ≥ 200 000 ₸         +20
новый получатель          +15
недавнее предупреждение   +25
уязвимый профиль          +15
синергия «звонок + буфер» +15
─────────────────────────────
максимум                  100
```

Порог принятия решения:

- `0–29` — **ALLOW**
- `30–59` — **COOL_DOWN**
- `60–84` — **GUARDIAN_APPROVAL**
- `85–100` — **BLOCK**

### Криптография

Подпись квитанции считается реальным `HMAC-SHA256` через Web Crypto API:

```
canonical = `${id}|${timestamp}|${sender}|${recipient}|${amount}|BCC`
signature = "BCC-" + первые 16 hex-символов, разбитые по 4
```

Ключ: `BCC-SHIELD-360-MASTER-CRYPTO-KEY-2026-KZ`.
При изменении суммы квитанции проверка возвращает `isValid: false` и показывает
сохранённый и пересчитанный хеши рядом.

### AI-сканер (опционально)

Без ключа API работает на детерминированной матрице казахстанских
мошеннических паттернов — демо никогда не падает.

Чтобы подключить LLM, создайте `.env.local`:

```bash
OPENAI_API_KEY=sk-...
```

Маршрут `POST /api/scam-analyze` объединит ответ модели с правилами и вернёт
поле `aiAssisted: true`.

## Сценарии для жюри

1. **Шторм атаки.** Нажмите **«Идеальный шторм»** — включится
   неизвестный звонок, вставка из буфера и сумма 450 000 ₸. Риск уходит в `BLOCK`,
   перевод блокируется с объяснением каждого фактора.
2. **Безопасный перевод.** Сбросьте атаку, выберите доверенного получателя и
   сумму ниже 200 000 ₸ — решение `ALLOW`, квитанция подписана.
3. **Кулдаун.** Неизвестный получатель + крупная сумма → `COOL_DOWN`, три
   чекбокса и таймер 10 секунд.
4. **GuardPay.** Одобрите или заблокируйте замороженный платёж; счётчик
   спасённых средств растёт при блокировке.
5. **Tamper-proof квитанция.** В TrustLens измените сумму квитанции и нажмите
   «Проверить подпись» — подпись станет невалидной, хеши разойдутся.
6. **Фишинг.** Прогоните четыре URL-пресета в песочнице TrustLens.
7. **Сканер.** Вставьте один из готовых скриптов, включите повышенную защиту
   (+25) и посмотрите, как растёт риск.

## Деплой на Vercel

1. Импортируйте репозиторий в Vercel.
2. Framework preset — **Next.js**, build command — `npm run build`.
3. При желании добавьте `OPENAI_API_KEY` в Environment Variables.
4. Deploy.
